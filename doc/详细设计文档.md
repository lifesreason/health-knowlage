### 1.2 核心业务流程详细设计

#### 1.2.1 认证与 Token 颁发流程

* **类**: `AuthService`
* **方法**: `validateWeChatLogin(code: string)`
* **逻辑伪代码**:
```typescript
async validateWeChatLogin(code) {
  // 1. 调用微信 API 获取 openid, session_key
  const { openid, session_key } = await this.wxService.code2Session(code);

  // 2. 查找或注册用户
  let user = await this.userRepo.findOne({ where: { openid } });
  if (!user) {
    user = await this.userRepo.save({ openid, nickname: '新用户' });
  }

  // 3. 生成 JWT Payload
  const payload = { sub: user.id, role: user.role };

  // 4. 存入 Redis 白名单 (单点登录控制)
  await this.redis.set(`token:${user.id}`, 'valid', 'EX', 7 * 24 * 3600);

  return {
    access_token: this.jwtService.sign(payload),
    is_bind_mobile: !!user.mobile_cipher //以此判断前端是否弹窗
  };
}

```



#### 1.2.2 首页推荐流算法实现

* **类**: `FeedService`
* **缓存策略**:
* **写**: 定时任务每 5 分钟计算一次 Top 1000 帖子，存入 Redis `ZSET`。
* **读**: 前 5 页读 Redis，第 6 页起读 MySQL。


* **Redis Key**: `feed:recommend:ids` (ZSet)
* **Score 计算公式**:
```typescript
// Score = (发布时间戳 / 1000) * 0.3 + (浏览量 + 点赞*5) * 0.7
// 注意：需归一化处理，防止时间戳权重过大
const timeScore = (post.createdAt.getTime() / 1000000); 
const heatScore = post.viewCount + (post.likeCount * 5);
const finalScore = timeScore + heatScore;

```



#### 1.2.3 内容审核状态机 (Audit Pipeline)

这是一个异步处理流程。

**时序图描述**:

1. **User**: 提交发布请求。
2. **Controller**: 写入 MySQL (`status=0`), 返回 `Success` 给用户。
3. **Service**: `EventEmitter.emit('post.created', postId)`。
4. **AuditListener**: 监听到事件，将 `postId` 推入 Redis Queue `audit:queue`。
5. **AuditProcessor (Consumer)**:
* 从 Queue 取出任务。
* 调用 `AliyunContentSecurityAPI`。
* **Case Pass**: Update DB `status=1`。
* **Case Fail**: Update DB `status=2`, `reject_reason='涉政/涉黄'`.

### 1.3 数据库访问层 (Repository)

使用 TypeORM `QueryBuilder` 优化复杂查询。

**获取圈子内的帖子列表 (含置顶逻辑)**

```typescript
async findByCircle(circleId: number, page: number) {
  return this.postRepo.createQueryBuilder('post')
    .leftJoinAndSelect('post.user', 'user') // 联查作者
    .where('post.circleId = :circleId', { circleId })
    .andWhere('post.auditStatus = 1') // 仅展示已发布
    .orderBy('post.isTop', 'DESC') // 优先置顶
    .addOrderBy('post.createdAt', 'DESC') // 其次按时间
    .skip((page - 1) * 10)
    .take(10)
    .getMany();
}

```

### 2.2 发布器组件 (Publisher.vue)

#### 2.2.1 直传 OSS 逻辑

为了减轻服务器带宽压力，采用前端直传。

1. **选择文件**: `uni.chooseImage({ count: 9 })`.
2. **获取签名**: Request `GET /api/oss/policy` -> 获得 `host`, `policy`, `signature`.
3. **上传循环**:
```javascript
async function uploadFiles(files) {
  const uploadTasks = files.map(file => {
    return uni.uploadFile({
      url: ossHost,
      filePath: file.path,
      name: 'file',
      formData: {
        key: `posts/${uuid()}.${ext}`,
        policy: policy,
        OSSAccessKeyId: accessId,
        signature: signature,
      }
    });
  });
  return Promise.all(uploadTasks);
}

```



### 2.3 视频播放器 (VideoSwiper.vue)

#### 2.3.1 预加载算法

* **组件**: `swiper` (vertical) containing `<video>` + `<image>` (cover).
* **状态**: `currentIndex`.
* **渲染逻辑**:

* **其他页**: 仅渲染 `<image>` 封面图占位。

### B.1 推荐流缓存策略（当前实现）

当前代码采用“分页结果缓存”而非“TopN ZSet”方案：

1. 缓存范围：`recommend` 前 5 页。
2. Key 格式：`sh:feed:home:recommend:{page}:{pageSize}`。
3. 存储结构：序列化后的分页结果 JSON。
4. 兜底策略：Redis 不可用时自动降级到进程内存缓存。
5. 可观测性：新增 `GET /stats/feed-cache` 输出命中/未命中/命中率等指标。

### B.2 机审执行链路（当前实现）

1. 发布时 `audit_status=0`，并将 `postId` 入队 `sh:audit:queue`。
2. 管理员可通过 `POST /audit/machine/run-once` 手动触发一次消费。
3. 处理结果写回 `biz_post.audit_status`，并记录 `sys_audit_log`。
4. 运行状态可通过 `GET /audit/machine/status` 查询。

### B.3 分享码接口

1. 提供 `GET /share/wxacode` 返回 `image/png`。
2. 前端可将该接口返回的小程序码与帖子封面合成分享海报。

* **全局配置**: `TTL=60s, Limit=60` (普通接口)。
* **发布接口**: `TTL=60s, Limit=1` (每分钟仅允许发1条)。
* **短信接口**: `TTL=60s, Limit=1`, `DayLimit=10`.

## 4. 异常处理规范

### 4.1 全局异常过滤器 (AllExceptionsFilter)

统一拦截 HTTP 异常和程序崩溃，返回标准 JSON。

```typescript
@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse();
    
    const status = exception instanceof HttpException 
      ? exception.getStatus() 
      : HttpStatus.INTERNAL_SERVER_ERROR;

    const message = exception instanceof HttpException
      ? exception.getResponse()
      : 'Internal Server Error';

    response.status(status).json({
      code: status, // 非0均为异常
      msg: message,
      data: null,
      timestamp: Date.now()
    });
  }
}

```

## 5. 开发注意事项 (Checklist)

1. **Uni-app 分包**: 确保 `Publisher` 和 `Settings` 页面在 `pages.json` 中配置为 `subPackages`，否则主包体积会超过 2MB 导致无法上传。
2. **日期格式**: 前后端交互统一使用 **时间戳 (Timestamp)**，前端负责格式化为 "刚刚", "3分钟前"。
3. **大字模式测试**: 开发页面时，必须随时在 Chrome 开发者工具中手动修改 `:root` 的 `--font-scale` 为 `1.4` 进行自测，防止文字溢出容器。
