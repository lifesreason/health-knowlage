## 1. 命名与设计规范 (Standards)

1. **表名**: 使用 `小写 snake_case`。
* `sys_`: 系统核心表 (用户、配置、日志)
* `biz_`: 核心业务表 (内容、圈子、评论)
* `rel_`: 多对多关系表 (关注、加入圈子)


2. **主键**: 统一使用 `id`，类型为 `BIGINT` (考虑到未来分库分表，建议使用 **Snowflake 雪花算法** 生成，而非自增)。
3. **通用字段**: 所有表必须包含以下字段：
* `created_at`: `datetime` (创建时间)
* `updated_at`: `datetime` (更新时间)
* `is_deleted`: `tinyint(1)` (逻辑删除: 0正常, 1删除)


4. **布尔值**: 使用 `tinyint(1)`，字段名以 `is_` 或 `has_` 开头 (如 `is_verified`).
5. **索引**:
* `uk_`: 唯一索引 (Unique Key)
* `idx_`: 普通索引 (Index)



---

## 2. 实体关系图 (ER Diagram)

* **Users** 与 **Posts** 是 1:N 关系。
* **Users** 与 **Circles** 是 M:N 关系 (通过 `rel_user_circle` 连接)。
* **Posts** 与 **Comments** 是 1:N 关系。
* **Posts** 与 **AuditLogs** 是 1:N 关系 (一条内容可能有多次审核记录)。

## 3. 详细表结构设计 (Schema Detail)

### 3.1 用户与权限域 (User Domain)

#### 3.1.1 用户基础表 `sys_user`

存储用户的核心身份信息。手机号强制加密。

```sql
CREATE TABLE `sys_user` (
  `id` bigint(20) NOT NULL COMMENT '分布式ID',
  `openid` varchar(64) NOT NULL COMMENT '微信OpenID',
  `unionid` varchar(64) DEFAULT NULL COMMENT '微信UnionID(预留)',
  `nickname` varchar(64) NOT NULL DEFAULT '用户' COMMENT '昵称',
  `avatar_url` varchar(255) DEFAULT '' COMMENT '头像URL',
  `mobile_cipher` varchar(128) DEFAULT NULL COMMENT '手机号(AES加密存储)',
  `role` tinyint(4) DEFAULT 0 COMMENT '角色: 0普通用户, 1认证医师, 9管理员',
  `font_scale` decimal(2,1) DEFAULT 1.0 COMMENT '适老化字体倍率(1.0-1.4)',
  `is_verified` tinyint(1) DEFAULT 0 COMMENT '是否实名认证',
  `status` tinyint(4) DEFAULT 1 COMMENT '状态: 1正常, 0封禁',
  `created_at` datetime DEFAULT CURRENT_TIMESTAMP,
  `updated_at` datetime DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  `is_deleted` tinyint(1) DEFAULT 0,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_openid` (`openid`),
  KEY `idx_mobile` (`mobile_cipher`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户基础表';

```

#### 3.1.2 医师认证表 `sys_doctor_profile`

### 3.2 社区核心域 (Community Domain)

#### 3.2.1 圈子表 `biz_circle`

社区的聚合单元。

```sql
CREATE TABLE `biz_circle` (
  `id` bigint(20) NOT NULL COMMENT '圈子ID',
  `name` varchar(32) NOT NULL COMMENT '圈子名称',

  `cover_url` varchar(255) DEFAULT NULL COMMENT '封面图',
  `member_count` int(11) DEFAULT 0 COMMENT '成员数(缓存)',
  `post_count` int(11) DEFAULT 0 COMMENT '帖子数(缓存)',
```

#### 3.2.2 用户-圈子关系表 `rel_user_circle`

```sql
CREATE TABLE `rel_user_circle` (
```

### 3.3 内容生产域 (Content Domain)

#### 3.3.1 帖子/内容表 `biz_post`

**核心表**。存储图文、视频。

```sql
CREATE TABLE `biz_post` (
  `id` bigint(20) NOT NULL COMMENT '帖子ID',

  `comment_count` int(11) DEFAULT 0 COMMENT '评论量',
```

#### 3.4.2 内容安全审核日志 `sys_audit_log`

```sql
CREATE TABLE `sys_audit_log` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT,
  `target_id` bigint(20) NOT NULL COMMENT '帖子ID',
  `audit_type` tinyint(4) NOT NULL COMMENT '1机器 2人工',

  `risk_label` varchar(32) DEFAULT NULL COMMENT '风险标签(涉黄/暴恐)',

  PRIMARY KEY (`id`),
  KEY `idx_target` (`target_id`)
```

## 4. Redis 缓存设计 (Cache Schema)

使用 Redis 处理高频读写和临时状态。

### 4.1 键值命名规范

格式：`project:module:key:id`

### 4.2 核心 Key 定义

| 模块 | Key 格式 | 类型 | TTL | 说明 |
| --- | --- | --- | --- | --- |
| **Auth** | `sh:auth:sms:{mobile}` | String | 5 min | 短信验证码 |
| **Auth** | `sh:auth:token:{userId}` | String | 7 days | JWT 白名单/版本控制 |
| **Feed** | `sh:feed:home:recommend` | ZSet | - | 首页推荐流 (Score=权重, Member=PostID) |
| **Post** | `sh:post:view:{postId}` | String | - | 视频/文章浏览量计数 (定时刷回DB) |
| **Audit** | `sh:audit:queue` | List | - | 待审核的内容ID队列 |
| **User** | `sh:user:profile:{userId}` | Hash | 1 hour | 用户基础信息缓存(含字体设置) |

## 5. 性能优化与运维策略

1. **索引优化**:
* `biz_post` 表的 `idx_feed_query` 是核心，必须包含 `status=1`。
* `rel_user_circle` 经常查询 "我加入的圈子"，所以 `idx_circle_user` 必不可少。


2. **读写策略**:
* **浏览量 (Views)**: 在 Redis 中 `INCR`，每 10 分钟异步批量更新回 MySQL `biz_post` 表，减少数据库写压力。
* **点赞 (Likes)**: 立即写入 MySQL (因涉及去重业务逻辑)，但列表页的点赞数读取 Redis 缓存。


3. **数据安全**:
* 数据库每日全量备份 (mysqldump)，Binlog 开启 ROW 模式以支持增量恢复。
* 手机号 (`mobile_cipher`) 解密密钥禁止硬编码在代码中，需通过环境变量注入。
