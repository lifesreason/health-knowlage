## 2. 全局规范 (Global Rules)

### 2.1 适老化设计规范 (核心)

* **字体倍率**：
* 默认正文 `16px` (32rpx)。
* 设置中提供“字体大小”滑块：标准(1.0x) / 大(1.2x) / 特大(1.4x)。
* **开发要求**：使用 CSS Variable `--font-scale` 控制，禁止写死 px 值。


* **交互热区**：所有点击类组件（图标、按钮、列表项）的响应区域不得小于 `44px * 44px`。
* **色彩对比**：文字与背景对比度需符合 WCAG AA 标准（如：纯白背景上使用 `#333333` 而非 `#999999`）。

### 2.2 交互反馈机制

* **Loading**：
* 局部加载：Skeleton（骨架屏），用于列表页首屏。
* 全局加载：Toast `icon: 'loading'`，用于提交表单、登录中。


* **Toast 提示**：
* 成功：显示“√”图标，文案如“发布成功”，停留 1.5s。
* 失败/警告：无图标或显示“!”，文案如“网络连接失败”，停留 2s。



### 2.3 异常状态定义 (Empty States)

| 场景 | 缺省图 (Image) | 文案 (Text) | 操作按钮 (Action) |
| --- | --- | --- | --- |
| **网络断开** | 插画_无网络 | 网络开小差了，请检查设置 | [刷新重试] |
| **列表为空** | 插画_空盒子 | 暂无相关内容，去别处看看 | [去首页] |
| **内容被删** | 插画_文件缺失 | 该内容已被发布者删除 | [返回] |
| **未登录** | 插画_未登录 | 登录后查看更多精彩内容 | [去登录] |

## 3. 功能模块详细需求

### 3.1 注册与登录体系 (Auth System)

**逻辑策略**：游客模式浏览，互动行为（点赞、评论、发帖、加入圈子）触发强制登录。

1. **登录流程**：
* **触发**：用户点击互动按钮。
* **Step 1**：调用 `wx.login` 静默获取 OpenID。
* **Step 2**：判断库中是否存在该 OpenID 对应的手机号。
* **有**：自动登录成功，继续原操作。
* **无**：弹窗提示“依据互联网法规，互动需实名认证”，显示 [微信一键授权手机号] 按钮。


* **Step 3 (降级)**：若用户拒绝微信手机号授权，跳转至表单页（输入手机号+短信验证码）。



### 3.2 首页 (Home)

1. **顶部导航**：
* **搜索框**：点击跳转搜索中间页。
* **Tabs**：推荐(Default) | 附近 | 关注。


2. **推荐流 (Feed)**：
* **样式**：混合排版（左文右图、大图视频、三图模式）。
* **逻辑**：
* 拉取 `status = 1` (已发布) 的内容。
* 排除 `blacklist` (黑名单) 用户内容。
* 排序：`Score = (CreateTime * 0.3) + (Views + Likes*5 + Comments*10) * 0.7`。




3. **分享定义 (Share)**：
* **分享到好友**：标题取文章标题，封面图取文章首图（4:3 裁剪）。
* **分享到朋友圈**：生成海报（背景图+二维码+标题），保存到相册。



### 3.3 圈子与发布闭环 (Community Loop)

**此模块为社区核心，补全了截图缺失的“生产端”。**

#### 3.3.1 圈子详情页

* **头部**：
* 展示：封面、名称、简介、成员数。
* **动作**：[加入圈子] / [已加入]（点击弹窗确认退出）。


* **发帖入口**：
* 悬浮按钮 `+`，仅在“已加入”状态下可用。未加入时点击提示“请先加入圈子”。



#### 3.3.2 发布器 (Publisher)

* **类型选择**：发图文 / 发视频。
* **编辑器**：
* **图文**：标题(50字内)、正文(2000字内)、图片(9张，支持拖拽排序/删除)。
* **视频**：上传(限3分钟，200MB内)，支持选择封面帧。
* **选项**：关联圈子(默认选中当前圈子，可修改)、添加话题(#)。


* **提交逻辑**：
1. **前端校验**：非空校验、敏感词正则预校验。
2. **上传**：媒体资源上传 OSS。
3. **创建**：写入 DB，状态默认为 `0` (审核中)。
4. **反馈**：Toast 提示“发布成功，审核通过后展示”，跳转回圈子页。



#### 3.3.3 内容状态机 (Content Status Machine)

* **审核中 (Status=0)**：仅作者本人在“个人中心-我的发布”可见，标记为“审核中”。
* **已发布 (Status=1)**：全平台可见。
* **审核驳回 (Status=2)**：作者可见，标记“未通过”，点击查看驳回原因（内容包含违规信息），支持编辑后再次提交。
* **用户删除 (Status=-1)**：软删除，全不可见。

### 3.4 视频沉浸流 (Video)

1. **交互**：
* 单列全屏，上下滑动切换。
* 单击：暂停/播放。双击：点赞（屏幕中心出现爱心动效）。


2. **侧边栏**：
* **头像**：点击跳转用户主页。
* **关注按钮**：点击变为“√”，再次点击无反应（取关需进主页，防止误触）。
* **数据**：点赞数、评论数、收藏数。


3. **流量策略**：
* 非 Wi-Fi 环境下，首次播放弹窗提示“正在使用移动数据，将消耗流量”。



### 3.5 个人中心 (Profile)

1. **基本信息**：
* 头像、昵称、UID。
* **标签**：若 user_role = 'doctor'，显示“认证医师”金标。


2. **数据栏**：
* 获赞与收藏 | 我关注的 | 加入圈子。


3. **我的服务**：
* **我的发布**：Tab分为“已发布”和“审核中/驳回”。
* **浏览历史**：本地缓存最近 100 条记录。
* **联系客服**：唤起微信原生客服会话。
* **设置**：进入设置页（含适老化字体设置）。

## 4. 后台管理需求 (Admin Requirements)

### 4.1 内容审核台 (Audit Dashboard)

* **人工审核流程**：
* 用户发布内容后，内容进入待审核列表。
* 管理员查看内容详情（图片/视频/文本）。
* 操作：[通过] / [驳回(选择原因)] / [封禁用户]。
* 驳回原因会同步给用户，用户可编辑后重新提交。


* **API审核设计（暂不实现）**：
* 已预留对接阿里云/腾讯云内容安全API的架构设计。
* 包含图片/视频鉴黄、鉴暴、OCR文字识别、文本反垃圾等功能模块。
* 后续可通过配置开关快速启用，实现"机初审+人复审"的升级流程。



### 4.2 认证管理

* **列表**：待审核的医师/达人认证申请。
* **详情**：查看上传的医师资格证/职称证图片。
* **操作**：[通过]（赋予 V 标） / [驳回]。

## 6. 性能与安全指标 (NFR)

1. **首屏加载**：冷启动首屏渲染时间 < 1.5s (分包预加载)。
2. **滑动帧率**：低端机 (Android 8.0+) 列表滑动 FPS > 50。
3. **并发处理**：支持万级用户同时在线，Feed 流接口响应 < 200ms。
4. **数据脱敏**：
* 接口返回的手机号必须脱敏 (`139****8888`)。
* 身份证号（认证用）不落地，仅用于即时核验或加密存储。
