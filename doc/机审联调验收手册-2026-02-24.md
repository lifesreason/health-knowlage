# 机审联调验收手册（2026-02-24）

## 1. 目标
- 在本地或测试环境快速验证机审链路是否可用：发布入队、消费者执行、状态回写、审核日志落库。
- 验证 `mock/aliyun/tencent` 三 Provider 的配置切换行为。

## 2. 前置条件
1. 后端服务已启动：`cd backend && npm run start`。
2. 数据库和 Redis 可连接。
3. 已配置机审开关与 Provider：
- `AUDIT_MACHINE_ENABLED=true`（或 `AUDIT_MACHINE_REVIEW_ENABLED=true`）
- `AUDIT_MACHINE_PROVIDER=mock|aliyun|tencent`
4. 管理员账号可登录：`/api/v1/auth/admin/login`。

## 3. 一键冒烟脚本

在后端目录执行：

```bash
cd backend
npm run smoke:audit
```

可选环境变量：

```bash
BASE_URL=http://localhost:3000/api/v1
ADMIN_USERNAME=admin
ADMIN_PASSWORD=admin123
# 可选：指定已有待审帖子
PENDING_POST_ID=123
# 可选：指定普通用户 token（否则脚本尝试 /auth/login）
USER_TOKEN=xxx
```

说明：
- 脚本路径：`/Volumes/gg/workspace/other/health-knowlage/backend/scripts/audit-smoke.sh`
- 若未提供 `PENDING_POST_ID`，脚本会尝试自动创建一条待审帖子。

## 4. 手工联调指令（可替代脚本）

1. 管理员登录：

```bash
curl -sS -X POST 'http://localhost:3000/api/v1/auth/admin/login' \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}'
```

2. 查看机审状态：

```bash
curl -sS 'http://localhost:3000/api/v1/audit/machine/status' \
  -H 'Authorization: Bearer <ADMIN_TOKEN>'
```

3. 手动消费一条队列：

```bash
curl -sS -X POST 'http://localhost:3000/api/v1/audit/machine/run-once' \
  -H 'Authorization: Bearer <ADMIN_TOKEN>'
```

4. 查询指定帖子审核历史：

```bash
curl -sS 'http://localhost:3000/api/v1/audit/history/<POST_ID>' \
  -H 'Authorization: Bearer <ADMIN_TOKEN>'
```

## 5. 验收标准
1. `GET /audit/machine/status` 返回关键字段：
- `enabled`
- `provider`
- `batchSize`
- `maxRetry`
- `queue`
2. `POST /audit/machine/run-once` 返回消费结果，且至少包含 `processed`。
3. `biz_post.audit_status` 与规则一致：
- 自动通过：`audit_status=1`
- 自动驳回：`audit_status=2`
- 人工复审：`audit_status=0`
4. `sys_audit_log` 新增对应日志，`details` 中可看到 provider、decision、action 等信息。

## 6. 常见问题
1. `provider_error_retry` 连续出现：
- 检查云厂商配置是否齐全（密钥、地域、业务线参数）。
2. 始终 `manual_review`：
- 检查 `AUDIT_MACHINE_AUTO_PASS` 与 `AUDIT_MACHINE_AUTO_REJECT` 开关。
3. 队列不下降：
- 检查 Redis 可达性与 `AUDIT_MACHINE_BATCH_SIZE`。
- 检查 `POST /audit/machine/run-once` 返回是否 `busy`。
